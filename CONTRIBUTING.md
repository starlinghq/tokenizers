# Contributing

Thanks for helping. Most contributions here are one of three kinds. Each has a short path.

| You want to | Start with |
| --- | --- |
| Use a model whose `tokenizer.json` does not load yet | A [tokenizer request](https://github.com/starlinghq/tokenizers/issues/new?template=tokenizer-request.yml) with the exception text |
| Add a profile for a model whose file already loads | [docs/adding-a-tokenizer.md](docs/adding-a-tokenizer.md) |
| Report output that differs from huggingface/tokenizers | A [conformance issue](https://github.com/starlinghq/tokenizers/issues/new?template=conformance-bug.yml) with the input and both outputs |

## Setup

You need the .NET SDK pinned in `global.json` (10.0.100 or a later patch). For the Python reference runners you also need Python 3.11 and [uv](https://docs.astral.sh/uv/).

```sh
git clone https://github.com/starlinghq/tokenizers && cd tokenizers
tools/fetch-assets.sh                                   # about 100 MB of pinned tokenizer.json files into .models/
STARLING_REQUIRE_ASSETS=1 dotnet test --solution Tokenizers.slnx
```

## Pull requests

- Keep each pull request to one change. Fixtures (`conformance/`, `tests/*/TestData/`) are generated by a runner under `reference/`, with the runner, its commit and the reference version stated. A new profile's fixtures can come with the profile. Changing existing fixtures always needs its own pull request.
- Add a `CHANGELOG.md` entry under `Unreleased` for anything a user can observe. A change in token ids, offsets or decoded text always counts.
- New behavior needs reference evidence from huggingface/tokenizers at a pinned version. "Looks right" is not evidence.
- Unsupported components keep failing at load. Do not make the loader accept a field it does not implement.
- `src/` takes no package dependency and never references Microsoft.ML.Tokenizers.
- Source adopted from another project is recorded in `PROVENANCE.md` and `THIRD-PARTY-NOTICES.md` in the same pull request.
- CI must pass on Linux and Windows, along with the release drill and ruff.

Coding agents: read [AGENTS.md](AGENTS.md). It carries the same rules in more detail.
