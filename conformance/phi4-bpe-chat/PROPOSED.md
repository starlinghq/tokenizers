# Proposed fixtures

Status: proposed (not yet accepted). Generated by `reference/tokenizer-json/run_tokenizer_json.py` at repository commit `ea2742105c40d2f937dbdc5a80c204a23c6b0e0f` (clean tree; `environment.json`) with huggingface/tokenizers 0.23.3 (`reference/tokenizer-json/requirements.txt`, Python 3.13), on the pinned `microsoft/Phi-4-mini-instruct` `tokenizer.json` at `cfbefacb99257ffa30c83adab238a50856ac3083` (15,524,095 bytes, SHA-256 `382cc235b56c725945e149cc25f191da667c836655efd0857b004320e90e91ea`).

This is the tokenizer of the Phi-4-mini model request (starlinghq/starling#109). The pre-tokenizer is tiktoken's o200k regex, declared as `Split` with `Removed` and `invert` true, followed by `ByteLevel` without its regex. There is no post-processor, so nothing is added; the model's chat template writes the role tags itself. Ten added tokens (200019-200028) have `rstrip` true, five of them not special.

```sh
python -I reference/tokenizer-json/run_tokenizer_json.py --profile phi4-bpe-chat \
    --asset .models/microsoft/Phi-4-mini-instruct/cfbefacb99257ffa30c83adab238a50856ac3083/tokenizer.json \
    --corpus conformance/corpus/tokenizer-corpus-v1.jsonl \
    --corpus conformance/corpus/tokenizer-corpus-qwen-bpe-v1.jsonl \
    --out conformance/phi4-bpe-chat --truncate 16 --without-special-tokens \
    --batch empty,ascii-sentence,chinese,emoji-zwj,bpe-special-adjacent,bpe-code-python \
    --pair-batch pair-ascii,pair-multilingual,pair-empty-second,bpe-pair-special \
    --pad-token '<|endoftext|>'
```

## Component reference data (same pull request)

`tests/Starlings.Tokenizers.Tests/TestData/o200k-bpe/` was written by `reference/o200k-bpe/run_o200k_reference.py --asset <the pinned file>` at the same commit, with the same tokenizers 0.23.3 environment:

- `unicode-classes.json`: `\p{Lu}`, `\p{Ll}`, `\p{Lt}`, `\p{Lm}`, `\p{Lo}` (and `\p{L}`, `\p{N}`, `\p{M}`, `\s`, which equal the existing 0.23.2 probe in `TestData/qwen-bpe/`) probed over every Unicode scalar value. `tools/generate-unicode-tables.py` builds the new tables from it.
- `split.jsonl.gz`: 12,420 rows, `Split(Regex(o200k), "removed", invert=True).pre_tokenize_str` on every string of one to three characters over 20 class representatives (8,420) and on 4,000 seeded random strings (seed 20261102). The runner fails if `"isolated"` without invert gives different pieces on any row.
- `phi4-differential.jsonl.gz`: 1,500 seeded random strings (seed 20261103) mixing the 12 Phi-4 added tokens, fragments of them, whitespace runs and text, encoded by the pinned file: ids, tokens, scalar offsets, decode both ways. (`environment.json` records the base seed 20261102; the runner seeds this dump with base + 1.) This is the evidence for `rstrip`, which the shared corpora do not reach.

## Runtime pipeline check

2026-11-02, not part of the fixtures: `AutoTokenizer.from_pretrained("microsoft/Phi-4-mini-instruct", revision="cfbefacb…")` with transformers 5.18.0 and tokenizers 0.23.2 (`reference/qwen-bpe/requirements-chat.txt`; no remote code) gives `TokenizersBackend` (`tokenizer_class` is `GPT2Tokenizer`). Its `backend_tokenizer.to_str()` differs from this file in one place: the post-processor is an identity `TemplateProcessing` (single `$A`, pair `$A $B:1`, no special tokens) where the file has `null`. On all 137 corpus cases, with and without special tokens, the live tokenizer and `Tokenizer.from_file` give identical ids, offsets, type ids, special-token masks and sequence ids, and `tokenizer(text[, pair], add_special_tokens=False)["input_ids"]` equals the file's ids. So the Hub file is pinned as the asset, not a derived pipeline.

## Decisions for the reviewer

1. Accept these as development fixtures for the `phi4-bpe-chat` profile, and the `TestData/o200k-bpe/` files as component reference data.
2. `--truncate 16` is chosen to exercise truncation on many cases, not the model's 128K-token context.
3. The live pipeline's identity post-processor is treated as equivalent to the file's `null` (evidence above). If you prefer the live pipeline as a derived asset, as for `qwen35-bpe-chat`, that is a follow-up.
4. The corpora have no case with the Phi-4 role or tool tags. A corpus file with those cases would come in a separate pull request; until then `added_tokens_special_and_non_special_in_text` and `added_token_rstrip` are experimental, backed by the 1,500-string differential.
