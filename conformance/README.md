# Conformance corpus (protected)

Reference inputs and expected outputs for every supported tokenizer profile (plan section 6.2). This directory is protected evidence: changes need maintainer review through CODEOWNERS, and implementation jobs do not edit it to make code pass.

Expected outputs come from the model's original tokenizer at a pinned version, generated by the reference runner in `model-pipeline`. Each case file records the generator, reference implementation, and version.

Coverage required per profile:

- ASCII, multilingual text, combining marks, emoji, surrogate pairs, whitespace, control characters, empty input.
- Added and special tokens, BOS/EOS, truncation, padding, masks, pair encoding, batch equivalence.
- Token IDs, decoded text, and offsets. Offsets state their unit: UTF-8 bytes, Unicode scalars, or UTF-16 code units.
- Delimiter and special-token look-alikes inside user text.
- Chat-template rendering and streaming UTF-8 boundaries for profiles that carry a template.

Release evaluation holdout sets (P-030) are curated by the maintainer and kept outside the paths implementation jobs can write.

Files here are byte-exact (`-text` in `.gitattributes`).
