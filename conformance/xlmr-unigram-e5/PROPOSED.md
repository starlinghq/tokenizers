# Accepted fixtures

Status: accepted as development fixtures by Mark on 2026-10-08 (PR #4). Not a release evaluation set: the corpus was written by an agent; the protected release set is P-030. The decisions below were taken as proposed.

Profile: `multilingual-e5-small/onnx-fp32-cpu` (`model-pipeline/registry/multilingual-e5-small/onnx-fp32-cpu/manifest.yaml`). e5-small is the working P0 candidate.

Generated by `model-pipeline/reference/encoder/run_e5.py` and `model-pipeline/reference/compare_tokenizers.py` at repository commit `001ced60d8d3f843168f97efc3f247495bdb97e2`, from `intfloat/multilingual-e5-small` at `614241f622f53c4eeff9890bdc4f31cfecc418b3`, on corpus `model-pipeline/reference/corpus/tokenizer-corpus-v1.jsonl`. `environment.json` lists asset digests and package versions.

| File | Contents |
| --- | --- |
| `tokenizer.jsonl` | Per case: ids, tokens, type ids, attention and special-token masks, offsets in Unicode scalars, UTF-16 code units and UTF-8 bytes, decode with and without special tokens; a 512-token truncation for long cases. Reference: the pinned `tokenizer.json` read by tokenizers 0.23.2. |
| `tokenizer-batch.json` | One right-padded batch (pad id 1) and its row-by-row equivalence with single encodes. |
| `embeddings.jsonl` | Per single-text case: the input ids used (from `tokenizer.jsonl`, truncated to 512) and the 384-dimension embedding from the sentence-transformers modules (Transformer, mean Pooling, Normalize) in PyTorch fp32 on CPU. |
| `parity.json` | Python ONNX Runtime on `onnx/model.onnx` against PyTorch on the same ids: last hidden state and pooled embedding errors, padded batches, and sentence-transformers' own tokenizer differences. |
| `tokenizer-implementations.transformers-5.json`, `tokenizer-implementations.transformers-4.json` | Ids from transformers (5.18.0; 4.57.6 fast and slow) and raw SentencePiece wherever they differ from the `tokenizer.json` reference. |

Decisions for the reviewer:

1. The tokenizer reference is the shipped `tokenizer.json`. sentence-transformers 6.1.0 on transformers 5.18.0 tokenizes 5 of 46 cases differently (lone `▁` around special-token literals and trailing spaces, U+0085), and slow SentencePiece differs on 6. Accept `tokenizer.json` as the reference, or pick another.
2. The embedding reference uses the `tokenizer.json` ids, not sentence-transformers' own tokenization, so the 5 cases above differ from what `SentenceTransformer.encode` returns today.
3. No `tolerances.yaml` is proposed here. Observed errors are in `parity.json` and `docs/m0/reference-runs.md`.
