# Provenance and change ledger

> Backlog ids (`P-0xx`), dates and "plan section" references in this ledger are records from the Starling planning repository, where this library was first built under a planning-era package name ([docs/repository-history.md](docs/repository-history.md)). The local-change ids `L1` and later continue here.

Every imported file, local change, and upstream contribution gets a row. Paths are relative to `src/StarlingHq.Tokenizers/`. Origin digests are SHA-256 of the origin file at the stated revision (first 16 hex digits). License texts are in [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md).

Two kinds of intake are recorded:

- **Adopted:** the file started as a copy of the origin file and keeps its structure (P-023 decision: Unigram algorithm files from dotnet/machinelearning).
- **Ported:** the file is new C# that reproduces the behavior of the origin source line by line. The reference implementation (huggingface/tokenizers v0.23.2) is the behavioral spec of the `tokenizer.json` interpreter (P-023 recommendation 2), so its Apache-2.0 notice applies to these files.

Written fresh, no third-party source: `TokenEncoding.cs`, `TokenizerOptions.cs`, `TokenizerExceptions.cs`, `Pipeline/TokenizerJsonLoader.cs` (field names and defaults, including BERT and WordPiece, follow the reference serde definitions), `Pipeline/Models.cs`, `Pipeline/QwenSplitPattern.cs` (a matcher for the two Qwen regexes written from the regex semantics, not from Oniguruma source), `Pipeline/BpeVocabulary.cs`, `Pipeline/BpeModelReader.cs` (same rules as the Unigram reader), `Pipeline/Utf8Util.cs`, `Pipeline/UnigramVocabulary.cs`, `Pipeline/UnigramVocabularyReader.cs` (JSON grammar per RFC 8259; decoding of escaped strings is delegated to System.Text.Json), `Pipeline/VocabularyTrie.cs` (radix sort plus multikey quicksort after Bentley and Sedgewick 1997, written from the published algorithm).

Not adopted (P-023 section 4 lists them): the ML.NET BPE path, `SentencePieceBaseModel.cs`, `SentencePieceTokenizer.cs` (its `CreateFromTokenizerJson` was read as a field-validation reference only), `SentencePieceNormalizationStep.cs`, `SentencepieceModel.cs`, and shared helpers. For the Qwen profiles the ML.NET BPE files (`BPETokenizer.cs`, `Word.cs`, `Merge.cs`, `Cache.cs`, `ByteToUnicodeEncoding.cs`, `RegexPreTokenizer.cs`) were read at `5a44dfdbf20d1b64211da313dfbaa9ffbf63ea5d` and not adopted: the merge loop is a few dozen lines and porting it from the reference's `word.rs` keeps its exact tie order and expiry check; ML.NET's model is string-keyed and loads from `vocab.json`/`merges.txt`, has no `ignore_merges`, and its regex pre-tokenizer is the .NET `Regex` path that mis-splits supplementary-plane letters (P-023 section 3.4).
